The problem

A pipeline sized for last year's fleet

Bluepeak operates distributed solar assets across a dozen sites, each inverter reporting telemetry every few seconds. When Meridian was engaged, the fleet had tripled in eighteen months and the ingest pipeline — a single-region managed database never designed for this write volume — was falling behind during peak generation hours, the exact moments when catching a failing inverter mattered most.

The response to volume growth had been to scale the database vertically, again and again. Cloud spend had grown faster than the fleet. Worse, the lag meant a failing inverter could go undetected for hours — lost generation that showed up as a line item nobody could explain until the monthly report.

The reframe that changed the architecture Bluepeak came to us asking to fix performance. We told them the real problem was that cost and reliability were fighting each other — and that a correctly-shaped pipeline would fix both at once.

Constraints

What couldn't move during the rebuild

  • No data loss during migration. Historical telemetry feeds regulatory and warranty reporting — years of it, non-negotiable.
  • Operators couldn't be retrained mid-crisis. The existing Grafana dashboards had to keep working throughout the migration.
  • Hardware diversity across sites. Four inverter vendors, four telemetry formats, inconsistent clock sync.
  • Spend reduction was the mandate, not a nice-to-have. The board had already flagged infrastructure cost as unsustainable.

The approach

Cost is a reliability feature

We moved hot telemetry to a columnar store, tiered the cold path to object storage, and right-sized the cluster against real load profiles instead of guesses.

Ingest & hot path

A Rust gateway that never falls behind

A lightweight ingest gateway normalizes all four vendor formats at the edge and writes into ClickHouse, which handles the write-heavy, append-only nature of telemetry far better than a general-purpose relational database ever will. Ninety days of hot data lives here for fast operator queries.

Right-sizing

The cluster was sized from real load, not habit

Before touching Kubernetes node counts, we captured two weeks of actual peak-generation traffic and load-tested against it. The cluster that resulted was smaller than the one it replaced — because the old one had been sized by incremental panic-scaling, not by data.

Results

One quarter post-migration

The new pipeline absorbs three times the write volume of the old one on a smaller, cheaper cluster — cloud spend is down 42% even as the fleet keeps growing. Anomaly detection, built on the same hot-path data, now flags a failing inverter within 11 minutes on average, down from a detection window that used to run into hours.

Operators kept their existing Grafana dashboards throughout — the migration was invisible to the people who depend on this data every day, which was the point.

"Meridian treats a deadline like an SLO. Nine months, zero slipped milestones, and the platform hasn't paged us once."
